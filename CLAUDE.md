# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

b8k-shell (GitHub haltia-de/shell; to become the DE Haltia, ADR 0004): the shell of the Lenovo YOGA Tablet 10 B8000-H port (device repository: haltia-de/device-lenovo-b8000h, locally /mnt/data/Projects/lenovo-b8000h-linux; ADR 0001 and CONTEXT.md there split device / shell / programs). It runs programs on a tablet without a desktop, for an older person. User-facing docs (`README.md`, `docs/shell.md`) are in Russian; code comments and commit messages in English, full sentences.

Layout: `bin/` and `sbin/` (scripts, installed to /usr/bin and /usr/sbin), `share/` (apps.conf, panel, ini files, icons, installed to /usr/share/b8k; until 2.0 install.sh leaves a symlink at each old /usr/local path), `themes/` (GTK themes b8k, b8k-cards, b8k-galculator), `waybar/` (/usr/share/b8k/waybar; /etc/xdg/waybar is the waybar package's), `etc/` (touchguard.conf and service, NetworkManager hook), `tools/` (C sources, their cross-build scripts and `native-build.sh` for the Alpine package), `wvkbd/` (patches and layouts of the on-screen keyboard). `build.sh` cross-builds the C parts in the `b8000h-build:3.24` container (output $WORK/tools, $WORK/out, WORK defaulting to /opt/b8000h; on this machine that is /mnt/data/b8000h-build); `install.sh [ROOT]` installs. The device's build-rootfs.sh fetches this repository at the tag pinned in its linux-port/apps/sources and runs both. A change here is a commit and a tag, then a new line in that file. The compositor (phoc-gpu), the session loop (desktop.start), b8k-suspend, b8k-usb and the other hardware helpers are the device's.

There is no test suite. CI (`.github/workflows/session.yml`, `ci/headless-session.sh`) starts the session under headless phoc with pixman in x86_64 Alpine and keeps a screenshot: a tie to the B8000-H shows up there. Otherwise verify on the tablet (see the device repository's CLAUDE.md, "Working on a connected tablet").

## Working on the tablet

- **Gotchas:**
  - The Python helpers run as `python3 /usr/bin/<name>`, so `pkill -x <name>` and `killall <name>` miss them. Find the pid with `ps -o pid,args`.
  - `b8k-focus watch` reads `apps.conf` only at start. After you change it, restart the watcher, or a new program never shows its state and never asks to close. Its `ps` line starts with `{b8k-focus}`, so the script path is the fourth field, not the third.
  - `pkill -f <pattern>` run over SSH also matches the remote shell that runs it, and kills your own command.
  - Killing `waybar` restarts the whole session and closes all programs. `kill -USR2 $(pidof waybar)` reloads its config and CSS in place.
  - Children of `b8k-launcher` that exit become zombies, because it `exec`s into waybar, which does not reap them. `pidof` still lists them.
  - Only one `wvkbd` may run: a second input-method client makes phoc misbehave.
  - The USB ACM console does not come back after s2idle, and the host ACL on `/dev/ttyACM0` is lost when the device re-enumerates.

## Tablet shell

The session in `/etc/local.d/desktop.start` runs `phoc-gpu -C /usr/share/b8k/phoc.ini -E b8k-launcher` (the old /usr/local paths still work through the symlinks) in a restart loop. `b8k-launcher` sets `NO_AT_BRIDGE`/`GTK_A11Y`, restores the brightness (`b8k-brightness --restore`), and starts the volume keys (`b8k-volume`), the keyboard (`b8k-keyboard` → `wvkbd-b8k`) and `b8k-focus watch`. It ends with `exec waybar`. If waybar dies, the whole session restarts. The panel is 120px wide on the left edge. `docs/shell.md` (Russian) describes the shell in full, including the palette. The parts that span files:

- **Home screen and panel.** `b8k-home` (C, `tools/b8k-home.c`) draws every program of the session's `apps.conf` as a tile on the background layer, with the time, the date and the weather from `~/.cache/b8k-weather.json`; the panel's home button (signal 8, `b8k-home toggle`) raises it to the top layer and `$XDG_RUNTIME_DIR/b8k-home.raised` marks that (a panel tap then lowers it instead of asking to close). A long press pins or unpins (`b8k-ask pin` → `b8k-apps pin|unpin` → `~/.config/b8k/panel`). The panel is home, the pinned buttons (default `panel`: firefox, max), a line, then slots `custom/slotN` (`b8k-launch slot N`: the Nth open program with signal 0, outlined) whose signals `b8k-apps` writes to `$XDG_RUNTIME_DIR/b8k/slots` and `b8k-focus` sends when an unpinned program opens or closes.
- **Closing.** Every program closes by the shell's "✕" at the top right (`b8k-close`, C, `tools/b8k-close.c`, overlay layer, 110x104), drawn as the last 88 px header button, red only while pressed. It shows while `$XDG_RUNTIME_DIR/b8k-launch/front` (written by `b8k-focus`) names a window or `b8k-launch/starting` ("id pid curtain-pid", written by `b8k-launch` while the curtain is up) exists, and the home screen is not up; `b8k-focus`, `b8k-launch` and `b8k-home` send it SIGUSR1 (`b8k-close update`) on changes. A tap runs `b8k-ask close-front`: a starting program is killed at once, a window is closed after the question. Raising the home screen kills the curtain. A panel tap on the program in front does nothing now. The theme `b8k` pads headers 110 px on the right and makes every header button 88 px high (its `:not(.b8k-any)` outweighs Adwaita's rules); Firefox's toolbars are padded 110 px (b8k-firefox-profile --shell).
- **Touch filter.** `b8k-touchguard` (C, `tools/b8k-touchguard.c`, OpenRC service before `local`) grabs the touchscreen and re-emits it through uinput ("b8k-touchguard touchscreen", the screen's 10 slots, our slot i for its slot i; only the axes the screen has, as libinput refuses min == max): a touch counts after 40 ms, a repeat within 300 ms / 140 units is dropped, a palm (size ≥ 73.33% of the screen's largest, pressure ≥ 39.21% of its highest, i.e. 11 of 15 and 100 of 255 here, or 3 contacts) cancels the touch as `MT_TOOL_PALM` and blocks until lift + 300 ms (on every open slot; 3 small fingers count as a palm, a two-finger pinch does not); with `multitouch = 1` (default) a second finger while the first is down starts a gesture that passes every finger live, without hold, landing point or buzz (one landing during the first's hold waits and goes down with it); `multitouch = 0` is one finger at a time; `/etc/b8k/touchguard.conf`. Sizes, pressures and the two radii are percent of the screen's axes (`73.33%`; the radii of its X extent), which the filter writes to `/run/b8k-touchguard.axes`; a plain number is the old absolute value, read and converted until 2.0 (the helper takes hundredths of a percent, `palm_major=7333`). `B8K_TOUCHGUARD_SCREEN=/dev/input/eventN` makes it read that device: `tools/touchguard-test.py` (root, on the tablet) feeds a uinput test screen to a second instance and prints what it hands out (its touches reach the app in front). SIGHUP (`rc-service b8k-touchguard reload`) rereads it with the screen still grabbed; SIGUSR1/SIGUSR2 turn decision logging on (15 min) and off, also into `/run/b8k-touchguard.events` when that file exists. `b8k-touchguard-setup` (power menu «Касания», `[touch]` with `home = no`) tunes every value live through `doas -n b8k-touchguard-conf set k=v` (root helper; its `ranges` keep a finger working) and reverts unless «Оставить» is tapped within 15 s. `b8k-sleep.py` rescans input devices every 30 s. Panel buttons use `on-click-release`; «‹» hides the panel at once (`b8k-tab`, no question).
- **Служебные.** The home tile «Служебные» (`[service]`, no `app_ids`) runs `b8k-ask service`, a fuzzel menu of Settings, «Касания», brightness, sound, rotation and the terminal (`--lines` follows the item count). An `apps.conf` section without `app_ids` is a menu, not a program: `b8k-launch start` runs it without a curtain and does not wait for a window, and `b8k-home` stays up under it. The chosen item opens through `b8k-launch tap`, which lowers the home screen. `[settings]`, `[term]` and `[touch]` are `home = no` (`b8k-apps` passes `home` through now).
- **Rotation.** `b8k-rotate` (Python, started by `b8k-launcher` when `wlr-randr` exists) reads the IIO accelerometer (`accelerometer=` in device.conf, else the first with `in_accel_x_raw`) at ~3 Hz through `in_mount_matrix` and, after 1 s steady, runs `wlr-randr --output <first or output=> --transform normal|90|180|270` (upright landscape reads y = -1 g on the B8000-H, the iio-sensor-proxy convention). Flat or half way keeps the current one. `b8k-rotate on|off|toggle|status` (`~/.config/b8k/rotate`, SIGUSR1 via `$XDG_RUNTIME_DIR/b8k-rotate.pid`); «Служебные» has «Выключить/Включить поворот». phoc turns touch with the output. The package depends on wlr-randr.
- **File chooser.** GTK3's chooser (MAX's «Сохранить как»/«Папка для файлов», Firefox) is styled by the theme: a real header (only `dialog.b8k-dialog` and `messagedialog` get the thin title edge), with the «Имя» label hidden so that saving fits 1160 px, and large rows. `share/b8k-shell.gschema.override` (91-b8k-shell) sets cwd start, folders first, no size or type column. The chooser writes all its keys to dconf on every close, so `b8k-launcher` resets them once (marker `~/.config/b8k/filechooser-1`) and adds the usual existing folders to `~/.config/gtk-3.0/bookmarks`. gsettings over SSH has no session bus: run it through the session's environment.
- **Video and music.** `b8k-video` and `b8k-music` live in repositories of their own (`/mnt/data/Projects/b8k-*` locally), each with a `sources/` package (one module per service: YouTube; Яндекс Музыка via yandex-music 3.2.1 and ya-passport-auth 1.8.0 wheels pinned in its `install.sh`). Videos play in `b8k-vplay` (C, now in the b8k-video repository, `vplay/b8k-vplay.c`, built by `build-rootfs.sh` through `vplay/build.sh` before that program's `install.sh`; it holds a logind `idle` inhibitor while it plays): libmpv's software renderer at the video's own size into wl_shm, scaled by phoc through `wp_viewporter`; 480p H.264 plays at 30 fps, 720p does not. A program holds the screen on or the system awake with a logind inhibitor (read by `b8k-sleep.py`). Never let `b8k-home` (or any program blocking signals for a signalfd) pass its signal mask to children: posix_spawn with a cleared mask and default handlers, or SIGTERM cannot stop them.
- **Buttons and state.**
  - **Per-person setup.** `b8k-apps` (run by `b8k-launcher` before anything else, and as `b8k-apps reload`) merges the built-in `apps.conf` (system programs without an X-B8K .desktop file: Firefox, calc, cards, term, settings), the `.desktop` programs (`X-B8K-Home`), `~/.config/b8k/apps.conf` and the panel file (`~/.config/b8k/panel`, else `share/panel`) into `$XDG_RUNTIME_DIR/b8k/apps.conf`, numbering panel signals 1–7 then 12+ (8–11 are the system modules), and writes `waybar.json`/`style.css`/`slots`/`aliases` there; waybar runs with `-c`/`-s` on them. `b8k-launch`, `b8k-focus`, `b8k-ask` and `b8k-splash` prefer that file; never hardcode a signal number. Program buttons share the CSS class `.app`; ids with dots need CSS escaping.
  - **Standards (ADR 0001).** `b8k-apps` adds `.desktop` files with `X-B8K-Home=true` as programs under their id; `X-B8K-Replaces=<old ids>` drops the old section and maps pinned ids to the new one. `b8k-badges` turns `com.canonical.Unity.LauncherEntry.Update` (count, count-visible; cleared when the sender leaves the bus) into the panel count (`$XDG_RUNTIME_DIR/b8k-badge/<id>` plus the button's signal, after the SigCgt check), finding the section by id or an `app_ids` word. `b8k-apps autostart` (from `b8k-launcher`) runs `/etc/xdg/autostart` entries with `X-B8K-Autostart=true` plus `~/.config/autostart`; the GNOME helpers there stay off. `X-B8K-Windows` adds helper windows (b8k-vplay) to a program's app_ids; `$XDG_RUNTIME_DIR/b8k/aliases` maps old ids for `b8k-launch`. Notifications go to mako (`mako.conf`, buzz on notify through `b8k-press notify`). `b8k-badges` also follows MPRIS players (`org.mpris.MediaPlayer2.*`, matched by `DesktopEntry`): Playing/Paused goes to `$XDG_RUNTIME_DIR/b8k-play/<id>` ("<status> <bus name>"), which `b8k-launch status`/`slot` mark as ▶/‖ before the label; a tap on the front program's button while it plays runs `b8k-ask media <id>` (Пауза/Продолжить, Стоп via gdbus), and `b8k-ask pin` lists the same first.
  - **Programs** live in repositories of their own (trudenboy/b8k-*), pinned in the device repository's `linux-port/apps/sources`, and meet the shell only through the standards above. There is no shared shell module for them any more (b8k_ui is gone): their shared code is the library b8k-compat; the look is the theme, the buzz is b8k-touchguard's.
  - A section of `apps.conf`: `label`, `icon` (shown by the start-up curtain), panel `signal` (0 = no button), window `app_ids`, `exec` (and `env`). `b8k-launch` reads it with awk on every call, `b8k-focus` and `b8k-ask` once at start. The `url`/`host` web-app fields and their chromeless Firefox windows are gone.
  - The terminal has no panel button or home tile: it is in «Служебные», and runs a root login shell (`b8k-term` → `doas -n b8k-rootsh`, a nopass rule written with `B8K_DOAS=all`, the default; without it doas asks for the password, then the user's shell). `install.sh`'s `B8K_DOAS` (all, shell, none) chooses `/etc/doas.d/z-b8k-shell.conf`; its rules name /usr/sbin and /usr/local/sbin until 2.0. Without the poweroff rule the power menu uses `loginctl`.
  - The USB port boots as a device. The ID pin (GPIO57) reads 1 whatever is plugged in, so patch 0044 drops the connector node and the power menu's «USB: клавиатура» runs `doas -n b8k-usb host` (the device's; looked up in /usr/sbin then /usr/local/sbin, no item without it): the role switch in `/sys/class/usb_role/*/role` plus the bq24190 OTG boost through a `regulator-output` consumer.
  - `b8k-launch` tests for a running Firefox with `alive`, not `pidof`. Programs the panel started become zombies when they exit, and `pidof` lists the zombies too.
  - `b8k-focus watch` writes `$XDG_RUNTIME_DIR/b8k-launch/state` and signals waybar with `SIGRTMIN+N`. It signals only when `/proc/<pid>/status` `SigCgt` shows that waybar catches that signal. An early signal killed waybar and caused the boot flashing.
- **Native programs instead of web apps.** Weather (`b8k-weather`, Gismeteo's open XML), news (`b8k-news`, RSS plus the story text from the page) and MAX (`b8k-max`) are Python GTK3 programs; no `apps.conf` section uses `url` now. Пасьянсы is Aisleriot (`sol`) with the `b8k-cards` GTK theme (`themes/b8k-cards`): GTK 3 CSS cannot hide widgets, so the menu bar and title are squeezed to nothing with negative margins; the toolbar and the game chooser are enlarged.
  - `b8k-max` runs on PyMax (the `maxapi-python` 2.4.1 wheel, pinned by sha256 in its `install.sh`, unpacked into `/usr/local/lib/b8k-max`) with telemetry off. `b8k-launcher` starts it with `--background` once a session exists in `~/.local/share/b8k-max/web.db`; closing the window only hides it, and the button reaches the same process through GApplication. It caches chats in `~/.cache/b8k-max/` and fetches photos only over https from `oneme.ru`/`max.ru`: the URLs come inside messages.
  - **Badges:** a program writes a count to `$XDG_RUNTIME_DIR/b8k-badge/<id>` and signals waybar (checking `SigCgt` first); `b8k-launch status` appends it to the label as a red number. `b8k-max` counts dialogs and groups, not channels.
- **Web-app windows** (the mechanism stays, nothing uses it).
  - Firefox's customization is the b8k-firefox repository (large toolbar, prefs, policies, `b8k-calm.js` keeping the keyboard down on a new window); `b8k-launch` runs its `b8k-firefox-profile --shell` before Firefox starts. Its chromeless web-app windows are gone (a page could pose under a trusted title); the `url`/`host` fields of apps.conf no longer open such windows. It picks up URLs that `b8k-launch` writes to `$XDG_RUNTIME_DIR/b8k-webapp.d/` and opens them in chromeless windows.
  - It builds `ALLOW` (page → title `U+2060 + label`) and `HOSTS` from the `url` and `host` of `apps.conf`. `HOSTS` limits each window to its own site; foreign pages move to a normal window.
- **Runtime files** go to `$XDG_RUNTIME_DIR`, which `pam_elogind` sets up through `b8k-session`. Never use `/tmp`.
- **Layers.**
  - waybar stays on the `top` layer. The keyboard runs on `bottom` (`--wayland-layer bottom`). Then phoc arranges the panel first, and the keyboard gets the width right of it.
  - With the keyboard on `top`, it squeezed the left panel to 440px. waybar asked for 800px again, and phoc looped (`Timeout ... configures pending` in the log), so the keyboard never appeared.
  - Moving waybar to `overlay` blanked the screen.
- **Dialogs.**
  - `b8k-ask` (the power menu and "close this program?") is a shell script around fuzzel in dmenu mode (`fuzzel-ask.ini`): C, Wayland only, on the overlay layer, so it shows in about 0.3 s (the Python GTK version took 2.3 s) and is always on top. fuzzel takes taps. Отмена, the last item, is preselected so that Enter does no harm. A choice buzzes through `b8k-press ask` (no signal).
  - `b8k-brightness` is a GTK window on the overlay layer through gtk-layer-shell (typelib `GtkLayerShell-0.1`), drawn as the same card as the fuzzel questions. b8k-paint's "start over?" uses the same fuzzel config. Programs share one header (`#dcdcda`, 88 px, title centred, "←" on the left). The palette table in `docs/shell.md` lists every colour, including the two light blues (`#c4dcf7` selected, `#99c1f1` disabled).
  - Firefox: b8k-firefox's `b8k-calm.js` takes the focus off the address bar once per window that opens on the home page, or the keyboard came up unasked.
  - The shell's GTK theme `b8k` (`themes/b8k`, Adwaita underneath; `b8k-launcher` exports `GTK_THEME=b8k`, which `b8k-sleep.py` passes on) gives programs the tall header with room for «✕» and large dialogs, so programs need not carry `HEADER_CSS` once they move to b8k-compat. Its selectors stay off what waybar draws.
  - Python GTK3 programs must call `gi.require_version("Gdk", "3.0")` as well as `Gtk`: GTK4 is installed too, and gi otherwise loads Gdk 4.
- **Device seams (ADR 0004).** The shell names no device: the backlight is `backlight=` in `/etc/haltia/device.conf` or the first in `/sys/class/backlight` (`b8k-brightness`, `b8k-sleep.py`); the power key `power_key=` there or the first input device with `KEY_POWER`; sleep the hook above; touch thresholds fractions of the axes; doas rules `B8K_DOAS`. Input events and `ff_effect` use native sizes, as x86_64 and aarch64 differ from armv7.
- **Power key** (`b8k-sleep.py`, root, nice -10).
  - A short press toggles the backlight on release. A one-second hold opens `b8k-ask power`. Ten minutes without input from any device (read ungrabbed) turn the screen off the same way (`IDLE_OFF`). 30 s after the screen goes off, the device's hook `/usr/lib/haltia/hooks/suspend` (root, no arguments, returns once awake; on B8000-H its b8k-suspend) or, without it, `freeze` into `/sys/power/state` runs s2idle.
  - Programs keep the screen on or the system up with a logind "block" inhibitor (`idle` / `sleep`; b8k-compat's `Awake` takes `sleep:idle`), which `b8k-sleep.py` reads through `ListInhibitors` (delay ones, NetworkManager's, do not count). The old b8k-awake files are no longer read.
  - BLS latches a new PWM duty only at the start of a frame, so after each change the handler runs `grim` into `/dev/null` to make phoc draw one.
  - Programs for the session start with the uid and an allowlisted environment of the real `/usr/bin/waybar` process. That uid must belong to `/etc/b8k/session-user`.
  - `b8k-ask power` calls `doas -n /usr/sbin/b8k-poweroff off|reboot`. The doas rule is written by `install.sh`.
- **Brightness and volume.**
  - `b8k-brightness` sets the level through logind `Session.SetBrightness` and keeps it in `~/.config/b8k/brightness`.
  - `b8k-volume` steps the PulseAudio sink by 5% (at most 100%) and signals `SIGRTMIN+10` (the speaker icon next to Wi-Fi over the battery).
  - The hardware `Speaker` gain is pinned at step 7 by a PulseAudio profile set (`pulse/`, selected by a udev rule), because steps 0–2 crackle.
- **Tap feedback.**
  - Every panel `on-click` starts with `b8k-press <id> <signal>` (`tools/b8k-press.c`, built by `build-b8k-press.sh`). It marks `$XDG_RUNTIME_DIR/b8k-press/<id>` for 300 ms, which `b8k-launch status` and `b8k-meter` turn into the `pressed` class, and buzzes the motor for 70 ms.
  - waybar ignores `:active` on touch. Panel signals: programs and slots 1–7 then 12+, home 8, 9 unused (was brightness), Wi-Fi and the speaker 10, battery 11. There is no drawer: Wi-Fi and the speaker sit in one row (`group/status`); brightness and mute are in «Служебные».
  - The motor is the `regulator-haptic` input device on the MT6320 VIBR LDO (patch 0039). Pulses shorter than about 50 ms are not felt.
  - The keyboard buzzes on every key press too (`wvkbd/0005-haptic.patch`, same 70 ms).
- **Start-up curtain.** `b8k-launch` runs `b8k-splash <id>` (C, `tools/b8k-splash.c`, built by `build-b8k-splash.sh` against the keyboard sysroot for cairo and pango) while a program has no window, and SIGTERMs it once the window is there. It draws the `icon` and `label` of `apps.conf` on the top layer right of the panel; SVG icons go through librsvg opened with `dlopen`, as the sysroot has no librsvg headers.
- **Hiding the panel.** The "‹" button under the clock runs `b8k-tab` (`tools/b8k-tab.c`, built by `build-b8k-tab.sh` against the keyboard's sysroot and wvkbd's `proto/`). It sends waybar `SIGUSR1` (invisible mode, exclusive zone 0) and puts a 120×44 "›" tab on the overlay layer exactly where the button was. A tap on the tab sends `SIGUSR1` again and exits. Keep the `#custom-hide` size (40 px + 2 px margins, 30 px icon) in step with `W`/`H` and the arrow in `b8k-tab.c`. `SIGUSR1` toggles, so never send it to waybar by hand while a tab is up.
- **Palette.** The frame is dark and the content light, in GNOME/libadwaita colours with the accent `#3584e4`. The palette table in `docs/shell.md` lists every file that repeats it. The keyboard colours are compiled into `wvkbd/config.b8k.h`.
