# AGENTS.md

This file provides guidance to coding agents working with code in this repository.

## What this is

haltia-shell (GitHub haltia-de/shell; b8k-shell until 2.0): the shell of the DE Haltia (ADR 0004), first on the Lenovo YOGA Tablet 10 B8000-H port (device repository: haltia-de/device-lenovo-b8000h, locally /mnt/data/Projects/haltia-de/device-lenovo-b8000h). The ADRs named here live in the project's root repository haltia-de/haltia (`docs/adr/000N-*.md`); ADR 0001 (`docs/adr/0001-three-layers.md`) and `CONTEXT.md` there split device / shell / programs. It runs programs on a tablet without a desktop, for an older person. User-facing docs (`README.md`, `docs/shell.md`) are in Russian; code comments and commit messages in English, full sentences.

Layout: `bin/` (what a person, a program or the device runs, installed to /usr/bin), `libexec/` (the shell's own parts and root helpers, installed to /usr/libexec/haltia), `share/` (apps.conf, panel, ini files, icons, installed to /usr/share/haltia). Until 3.0 install.sh leaves the old names as symlinks (/usr/bin/b8k-*, /usr/sbin/b8k-*, /usr/share/b8k/*, the themes b8k*, and what the B8000-H images up to v1.1.0 name in /usr/local: bin/b8k-session, bin/b8k-launcher, share/b8k/phoc.ini, sbin/b8k-{rootsh,poweroff,touchguard-conf,panel-signal}, with their doas lines; a session loop read at boot keeps calling those), and `haltia-upgrade` (package post-install/post-upgrade, or install.sh on a running system) moves /etc/b8k into /etc/haltia with a symlink back, carries the touch filter's runlevel over to haltia-touchguard and restarts the root services; the shell's own ~/.config/b8k files move on the next session start. Readers fall back to the old places, X-B8K-* keys and B8K_* variables until 3.0, `themes/` (GTK themes b8k, b8k-cards, b8k-galculator), `waybar/` (/usr/share/haltia/waybar; /etc/xdg/waybar is the waybar package's), `etc/` (touchguard.conf and service, NetworkManager hook), `tools/` (C sources, their cross-build scripts and `native-build.sh` for the Alpine package), `wvkbd/` (patches and layouts of the on-screen keyboard). `build.sh` cross-builds the C parts in the `b8000h-build:3.24` container (output $WORK/tools, $WORK/out, WORK defaulting to /opt/b8000h; on this machine that is /mnt/data/b8000h-build); `install.sh [ROOT]` installs. The device's build-rootfs.sh fetches this repository at the tag pinned in its linux-port/apps/sources and runs both. A change here is a commit and a tag, then a new line in that file. The compositor (phoc-gpu), the session loop (desktop.start), b8k-suspend, b8k-usb and the other hardware helpers are the device's.

`tests/` holds the unit tests: `haltia-update` against a fake apk (`tests/fake-apk`), `python3 -m unittest discover -s tests`, run by the session workflow's `tests` job. Beyond them, CI (`.github/workflows/session.yml`, `ci/headless-session.sh`) starts the session under headless phoc with pixman in x86_64 Alpine and keeps a screenshot: a tie to the B8000-H shows up there. Otherwise verify on the tablet (see the device repository's CLAUDE.md, "Working on a connected tablet").

## Sessions and architectures

The package builds for armv7, aarch64 and x86_64 (release.yml, haltia-de/ci). B8000-H images start the session themselves (desktop.start: haltia-session, phoc-gpu). Display managers (tinydm, greetd) use `/usr/share/wayland-sessions/haltia.desktop` → `haltia-wayland-session`: the compositor from `compositor=` in `/etc/haltia/device.conf`, else `phoc`, with `/usr/share/haltia/phoc.ini` (or `HALTIA_PHOC_CONFIG`) and `-E haltia-launcher`, through `dbus-run-session` when there is no session bus; it sets `XDG_CURRENT_DESKTOP=Haltia:GNOME` unless the desktop already names GNOME (GNOME Settings needs it). The session CI starts it this way.

## Working on the tablet

- **Gotchas:**
  - The Python helpers run as `python3 /usr/bin/<name>`, so `pkill -x <name>` and `killall <name>` miss them. Find the pid with `ps -o pid,args`.
  - `haltia-focus watch` reads `apps.conf` only at start. After you change it, restart the watcher, or a new program never shows its state and never asks to close. Its `ps` line starts with `{haltia-focus}`, so the script path is the fourth field, not the third.
  - `pkill -f <pattern>` run over SSH also matches the remote shell that runs it, and kills your own command.
  - Killing `waybar` restarts the whole session and closes all programs. `kill -USR2 $(pidof waybar)` reloads its config and CSS in place.
  - Children of `haltia-launcher` that exit become zombies, because it `exec`s into waybar, which does not reap them. `pidof` still lists them.
  - Only one `wvkbd` may run: a second input-method client makes phoc misbehave.
  - The USB ACM console does not come back after s2idle, and the host ACL on `/dev/ttyACM0` is lost when the device re-enumerates.

## Tablet shell

The session in `/etc/local.d/desktop.start` runs `phoc-gpu -C /usr/share/haltia/phoc.ini -E haltia-launcher` (the old b8k names still work through the symlinks) in a restart loop. `haltia-launcher` sets `NO_AT_BRIDGE`/`GTK_A11Y`, restores the brightness (`haltia-brightness --restore`, in the background), and starts the keyboard (`haltia-keyboard` → `wvkbd-b8k`) and `haltia-focus watch`. The session's daemons (home, close, focus watch, volume, rotate, badges) run under `libexec/haltia-keep --session`, which starts one that ends again a second later (more than 5 ends a minute: off for 5 min, then again; a clean exit within 3 s: another copy runs or nothing to do, left off) while the compositor's socket is the one it started with (checked before every start); haltia-launcher ends every keeper of the user first, as a session starts, and the keeper closes fds 3–9; a SIGTERM to the daemon alone (haltia-restart, `haltia-apps reload`) brings up the new version, so those two only stop a kept daemon. Never start one under a `flock` you hold: it inherits the lock's fd. It ends with `exec waybar`; what the panel need not wait for (the portal's stand-in, volume keys, rotation, badges, Сообщения, autostart, update notifications: Python with GObject, 1-3 s each after a boot) starts from `after_panel` once the launcher's comm reads waybar, plus 2 s. Keep a Python start off the path before `exec waybar`. If waybar dies, the whole session restarts. The panel is 120px wide on the left edge (along the bottom, 100 px high, while the screen stands portrait). `docs/shell.md` (Russian) describes the shell in full, including the palette. The parts that span files:

- **Home screen and panel.** `haltia-home` (C, `tools/haltia-home.c`) draws every program of the session's `apps.conf` as a tile on the background layer, with the time, the date and the weather from `~/.cache/haltia-weather.json` (or `~/.cache/b8k-weather.json`; the panel's home button (signal 8, `haltia-home toggle`) raises it to the top layer and `$XDG_RUNTIME_DIR/haltia/home.raised` marks that (a panel tap then lowers it instead of asking to close). A long press pins or unpins (`haltia-ask pin` → `haltia-apps pin|unpin` → `~/.config/haltia/panel`). The panel is home, the pinned buttons (default `panel`: firefox, max), a line, then slots `custom/slotN` (`haltia-launch slot N`: the Nth open program with signal 0, outlined) whose signals `haltia-apps` writes to `$XDG_RUNTIME_DIR/haltia/slots` and `haltia-focus` sends when an unpinned program opens or closes.
- **Closing.** Every program closes by the shell's "✕" at the top right (`haltia-close`, C, `tools/haltia-close.c`, overlay layer, 110x104), drawn as the last 88 px header button, red only while pressed. It shows while `$XDG_RUNTIME_DIR/haltia/launch/front` (written by `haltia-focus`) names a window or `haltia/launch/starting` ("id pid curtain-pid", written by `haltia-launch` while the curtain is up) exists, and the home screen is not up; `haltia-focus`, `haltia-launch` and `haltia-home` send it SIGUSR1 (`haltia-close update`) on changes. A tap runs `haltia-ask close-front`: a starting program is killed at once, a window is closed after the question. After «Закрыть» a curtain «Закрываю «…»…» (`haltia-splash ID TEXT`) covers it while the window is asked to close; more windows of the program (a «save?» dialog) mean it answers and the curtain goes; the window still there after 5 s means it hangs, and `haltia-stop ID APP_ID...` (libexec) SIGTERMs, then 2 s later SIGKILLs the whole program: the pid `haltia-launch` wrote to `haltia/launch/pid/ID` ("PID START", taken only while that pid has that start time; never a SHELL process or anything below one), else processes whose command (python3 SCRIPT counts as SCRIPT) is the section's exec or an app id, with all descendants; an autostart entry `ID.desktop` starts again in the background (`haltia-apps autostart NAME`). Raising the home screen kills the curtain. A panel tap on the program in front does nothing now. The same process draws a second square at the top left, right of the panel (exclusive zone 0; portrait: the screen's top left corner), where a header's «←» stands: «⇤», an arrow into a bar pointing at the panel's home button (down in portrait), blue while pressed, shown only while the program in front has no step back. Programs say so with the GTK action `app.back` (enabled while there is a step back; their «←» binds to it; docs/plan-minimize.md), which GLib exports as `org.gtk.Actions`; `haltia-badges` (BackStep) follows the front program's action into `haltia/launch/back` and SIGUSR1s haltia-close: "APP_ID 1" (a step back), "APP_ID 0" (none: the button) or "APP_ID -" (no action, or not on the bus: no button, as the program's own «←» stands there; asked again on NameOwnerChanged). The condition: the program owns its app id on the bus (no `NON_UNIQUE`) and its windows' Wayland app_id is that id. Programs not our own are named with `back = none` in apps.conf (Firefox, galculator, sol) and always get 0; their themes and the Firefox profile leave 110 px on the left. Not under a curtain or over the home screen. A tap runs `haltia-launch home`: `haltia-home show`, then `haltia-press` on the program's panel button (or slot 1). haltia-rotate runs `haltia-close update` after a turn, for the arrow. The theme `b8k` pads headers 110 px on the right and makes every header button 88 px high (its `:not(.b8k-any)` outweighs Adwaita's rules); Firefox's toolbars are padded 110 px (b8k-firefox-profile --shell).
- **Touch filter.** `haltia-touchguard` (C, `tools/haltia-touchguard.c`, OpenRC service before `local`) grabs the touchscreen and re-emits it through uinput ("haltia-touchguard touchscreen", the screen's 10 slots, our slot i for its slot i; only the axes the screen has, as libinput refuses min == max): a touch counts after 40 ms, a repeat within 300 ms / 140 units is dropped, a palm (size ≥ 73.33% of the screen's largest, pressure ≥ 39.21% of its highest, i.e. 11 of 15 and 100 of 255 here, or 3 contacts) cancels the touch as `MT_TOOL_PALM` and blocks until lift + 300 ms (on every open slot; 3 small fingers count as a palm, a two-finger pinch does not); with `multitouch = 1` (default) a second finger while the first is down starts a gesture that passes every finger live, without hold, landing point or buzz (one landing during the first's hold waits and goes down with it); `multitouch = 0` is one finger at a time; `/etc/haltia/touchguard.conf`. Sizes, pressures and the two radii are percent of the screen's axes (`73.33%`; the radii of its X extent), which the filter writes to `/run/haltia/touchguard.axes`; a plain number is the old absolute value, read and converted until 2.0 (the helper takes hundredths of a percent, `palm_major=7333`). `HALTIA_TOUCHGUARD_SCREEN=/dev/input/eventN` makes it read that device: `tools/touchguard-test.py` (root, on the tablet) feeds a uinput test screen to a second instance and prints what it hands out (its touches reach the app in front). It runs under `supervise-daemon` (respawn 2 s, at most 10 a minute; a lost screen exits 1 and the next start looks it up again) and writes its own `/run/haltia/touchguard.pid` (the service's pidfile is the supervisor's; `haltia-upgrade` moves one started the old way under the supervisor). SIGHUP (`rc-service haltia-touchguard reload`) rereads it with the screen still grabbed; SIGUSR1/SIGUSR2 turn decision logging on (15 min) and off, also into `/run/haltia/touchguard.events` when that file exists. `haltia-touch-settings` («Служебные» → «Касания», `[touch]` with `home = no`) tunes every value live through `doas -n haltia-touchguard-conf set k=v` (root helper; its `ranges` keep a finger working) and reverts unless «Оставить» is tapped within 15 s. A program that answers touches itself (`X-Haltia-Own-Feedback=true` in its .desktop file; `haltia-apps` writes `feedback = own`) gets no tap or long-press buzz while it is in front: `haltia-focus` keeps `$XDG_RUNTIME_DIR/haltia/quiet-taps`, which the filter (root, session user from session-user) only lstats, regular file of that uid, and ignores while `home.raised` exists. `haltia-sleep` rescans input devices every 30 s. Panel buttons use `on-click-release`; «‹» hides the panel at once (`haltia-tab`, no question).
- **Служебные (gone with 2.6).** The home tile is now `[settings]`; what was rare and for the helper is in Настройки → «Для помощника». `haltia-ask service` stays for whoever calls it by name.
- **Rotation.** `haltia-rotate` (Python, started by `haltia-launcher` when `wlr-randr` exists) reads the IIO accelerometer (`accelerometer=` in device.conf, else the first with `in_accel_x_raw`) at ~3 Hz through `in_mount_matrix` and, after 1 s steady, runs `wlr-randr --output <first or output=> --transform normal|90|180|270` (upright landscape reads y = -1 g on the B8000-H, the iio-sensor-proxy convention). Flat or half way keeps the current one. `haltia-rotate on|off|toggle|status` (`~/.config/haltia/rotate`, SIGUSR1 via `$XDG_RUNTIME_DIR/haltia/rotate.pid`); «Служебные» has «Выключить/Включить поворот». phoc turns touch with the output. Between landscape and portrait it writes `$XDG_RUNTIME_DIR/haltia/orientation`, runs `haltia-apps panel` (portrait: waybar `position: bottom`, height 100, the status's three icons stacked (Wi-Fi, speaker, battery), no hide button, buttons share 500 px less 44 px kept for the recording mark, which otherwise pushed the clock off the row) and sends waybar SIGUSR2 only after the SigCgt check, retrying; it SIGTERMs `haltia-tab` first. `haltia-launcher` removes the orientation file at start; `haltia-splash` reads it for its margin. The package depends on wlr-randr.
- **Settings.** `haltia-settings` (GTK 3, `io.github.haltia_de.Settings`, `[settings]`, a home tile) holds everything one sets: two panes in landscape (sections with a summary each on the left, `SIDEBAR` 360 px), one at a time with «←» on a screen narrower than 1000 px (decided by the monitor, not the window, which the list would keep wide; the stack is not homogeneous for the same reason). Sections: network (NetworkManager via `NM-1.0`; a new network's password is stored in the system connection, so no secret agent), sound and vibration (pactl; the touch filter's `buzz_ms` through `haltia-touchguard-conf`), screen (brightness through haltia-brightness's module, rotation, off after N min and on while charging in `~/.config/haltia/screen`, read by `haltia-sleep` every 30 s), panel and home screen (switches and ↑↓ writing `~/.config/haltia/panel` and `home`, then `haltia-apps reload`; at most 3 pinned, never off both, Настройки always home), notifications (`~/.config/haltia/notifications`; `haltia-mako config` writes mako's config into the runtime dir, `haltia-mako buzz` is its on-notify), date and time (timedated from openrc-settingsd; `share/polkit/50-haltia.rules` lets the active session of a wheel member set it), updates, about. A long press on «О системе» adds «Для помощника» until the window closes: the touch page (`haltia-touch-settings`' `Setup(embedded=True)`, the whole window, its CSS scoped to `.touch`, `leave()` undoes what was not kept), the terminal, the update log, going back to any snapshot, and hiding programs altogether. A page's inner pages are `subpages` in the window's stack (`updates/notes`, `helper/log`...), opened with `open_subpage`. Nothing blocks the GTK thread: a page is built when first opened (the list takes each class's `title`), the line under each section is its class's `peek()` run through `background(fetch, apply)` (a worker thread for commands, files and D-Bus, never GTK; the result applied with `idle_add`), each page's `refresh()` reads its status the same way (Updates reads `haltia-update state` and `haltia-restart pending` through one cached `fetch()` that the list's line and the page share for 10 s, `fresh=True` after an update and in `poll`, which keeps one read in flight; once the page exists the line comes from its `line()`; `fetch` never raises), `background(..., latest=KEY)` applies only the newest of a key's reads, `fallback=` is applied when fetch raises, `serial=True` queues the list's peeks on one worker, NetworkManager's client comes from `NM.Client.new_async`, and setters that need no answer go through `spawn()`. Keep `run()` off the GTK thread. `--page NAME` opens a section; a second call switches the running instance. The package depends on dconf, the icon themes, the Adwaita sans font, glib-networking, iso-codes, openrc-settingsd and polkit-elogind, which came only with gnome-control-center before.
- **Updates.** `haltia-update` (libexec, root via doas; docs/plan-updates.md): check, changes (AppStream releases from the new .apk's metainfo, the Russian text when there is one, kept per version in `notes/`), upgrade [NAME...] (all, or one program with what it needs; preflight, snapshot of versions plus the old .apk files, elogind-inhibit, `apk upgrade --cache-predownload --progress-fd`, printing `stage S`/`progress N` lines, rollback on failure and the failed snapshot dropped, then pending and the health checks a minute later; pending.json records `time` and `session` (anything but Haltia programs and their kit changed: the shell, a system package), and such an update is marked good only by checks in a session whose waybar started after it (`session_since`), as the session that ran the upgrade still has the old code in memory; a closed window (BrokenPipe on stdout) turns `log` to /dev/null instead of ending apk mid-transaction), rollback [ID [NAME...]] (puts back only what the update changed and differs now, from the kept files, then a repository for one without a file; world is then rewritten from the one before the rollback, with Haltia's packages pinned and held (never system ones), and applied with a plain `apk add`, which drops what the upgrade added; any failure after the files puts that world back, keeps the snapshot and pending.json and returns 1; marks the snapshot's `rolled_back`), health (a check that hangs past 120 s fails; health, boot and session-start wait for the lock at most 60/60/10 s), state (one JSON for the window), news (what it did by itself, for `haltia-update-notify`), health, session-start, boot. apk 3.0.8's `apk fetch name=version` fails ("unable to select package"), so snapshots download the old .apk from the repository URL; apk checks the signature on rollback. State in /var/lib/haltia/update, five snapshots kept, apk calls use `--wait`. haltia-sleep looks for updates (and with auto=yes installs them) when the screen goes off on the charger, at most every 20 h, and notifies when the screen comes back. Notifications go through `haltia-update-notify` (Gio D-Bus, as notify-send is not installed; a tap opens Настройки → Обновления), from haltia-launcher after the session start and from haltia-sleep. Настройки → Обновления: state and «Проверить», progress, each program with «Обновить» (row tap: «Что нового», a subpage `updates/notes` in the window's stack), «Обновить всё», updating by itself, past updates; their «Вернуть прежнюю» and «Откатить последнее обновление» show only once «Для помощника» is open (`helper_open()`; opening it refills the history). After an update or a rollback the new versions start (`libexec/haltia-restart PACKAGE...`, from Настройки with `--ask` and from haltia-update-notify, which reads the packages as `news`' third field): `haltia-apps reload`, then each updated running program without a window is restarted through haltia-stop, one with a window is asked about (`haltia-ask restart LABEL`, which waits for the ask lock instead of counting a busy lock as yes) or, without `--ask`, listed in `$XDG_RUNTIME_DIR/haltia/restart-pending` (`haltia-restart pending` prunes it by process start time; Обновления shows it) and restarted in the background when haltia-focus sees its last window close (`haltia-restart closed APP_ID...`); for haltia-shell only the windowless helpers restart (volume, rotate, badges, portal), the rest at the next session. py3-haltia-kit counts as every .desktop program. The shell's own release notes are NEWS.md (Russian and English, newest first); the metainfo's `<releases>` are written from it by haltia-de/ci's `news.py metainfo NEWS.md data/io.github.haltia_de.Shell.metainfo.xml` (locally `python3 ../ci/news.py ...`), and the release CI checks they match. `changes` reads the repository's AppStream catalog first (`appstream.xml.gz` next to the indexes, built by haltia-de/packages' build-appstream.py from the packages' metainfo; fetched by `check` with ETag into /var/lib/haltia/update/catalog), and downloads the package only when the catalog lacks that version.
- **GTK 4.** Only GNOME Settings (and its goa/libnma dialogs), now replaced by haltia-settings, is GTK 4/libadwaita; it takes no theme, so `haltia-launcher` writes `~/.config/gtk-4.0/gtk.css` (an `@import` of `/usr/share/haltia/gtk-4.0.css`, only when one has none) and `settings.ini` (`gtk-decoration-layout=:`): the GTK 3 theme's header, fonts and room for «✕». gnome-control-center refuses to run without `XDG_CURRENT_DESKTOP` containing GNOME (desktop.start sets Phosh:GNOME; a test shell without it fails).
- **Simple file chooser.** Every program's chooser is haltia-files' (`haltia-files --portal`, `org.freedesktop.impl.portal.desktop.haltia`, app id `io.github.haltia_de.FileChooser`, repository haltia-de/files, locally /mnt/data/Projects/haltia-de/files): places, filters as buttons, tiles or rows, one-screen saving with a free name. Programs reach it through the portal: GTK 3 with `GTK_USE_PORTAL=1`, Firefox by itself once that is set. Without xdg-desktop-portal (the B8000-H) `libexec/haltia-portal` (Python Gio) owns `org.freedesktop.portal.Desktop` with FileChooser (passed to the backend; GTK 3 crashes on a Response without `uris`, so it always adds an empty list), OpenURI (http/https/mailto/tel/file, launched with GIO's default) and an empty Settings (GTK and Firefox fall back to dconf); haltia-launcher starts it, writes its activation file into `$XDG_RUNTIME_DIR/dbus-1/services` only when no real portal's service file exists, and marks `$XDG_RUNTIME_DIR/haltia/portal`. With that mark haltia-launcher and haltia-launch export `GTK_USE_PORTAL=1` unless `~/.config/haltia/chooser.conf` has `simple = no` (Настройки → «Для помощника», which also has `all`: home, system, hidden files). GTK 3 treats a failed portal call as Cancel, never falling back, so never set the variable without a working portal. Register D-Bus objects in the bus-acquired callback: a call that activated the process arrives as soon as the name is taken. «✕» on the chooser is Отмена without a question (haltia-ask). Cold start about 3.5 s, warm about 1 s; the backend stays 5 min (about 40 MB), the stand-in about 20 MB.
- **File chooser (GTK's own, when the simple one is off).** GTK3's chooser (MAX's «Сохранить как»/«Папка для файлов», Firefox) is styled by the theme: a real header (only `dialog.haltia-dialog` (and the old `.b8k-dialog`) and `messagedialog` get the thin title edge), with the «Имя» label hidden so that saving fits 1160 px, and large rows. `share/haltia-shell.gschema.override` (91-haltia-shell) sets cwd start, folders first, no size or type column. It also makes `org.gnome.desktop.interface gtk-theme` 'Haltia', so a GTK 3 program started without the session's GTK_THEME (D-Bus activation, a terminal, another service) is themed too. The chooser writes all its keys to dconf on every close, so `haltia-launcher` resets them once (marker `~/.config/haltia/filechooser-1`) and adds the usual existing folders to `~/.config/gtk-3.0/bookmarks`. gsettings over SSH has no session bus: run it through the session's environment.
- **Video and music.** `b8k-video` and `b8k-music` live in repositories of their own (`/mnt/data/Projects/haltia-de/*` locally), each with a `sources/` package (one module per service: YouTube; Яндекс Музыка via yandex-music 3.2.1 and ya-passport-auth 1.8.0 wheels pinned in its `install.sh`). Videos play in `b8k-vplay` (C, now in the b8k-video repository, `vplay/b8k-vplay.c`, built by `build-rootfs.sh` through `vplay/build.sh` before that program's `install.sh`; it holds a logind `idle` inhibitor while it plays): libmpv's software renderer at the video's own size into wl_shm, scaled by phoc through `wp_viewporter`; 480p H.264 plays at 30 fps, 720p does not. A program holds the screen on or the system awake with a logind inhibitor (read by `haltia-sleep`). Never let `haltia-home` (or any program blocking signals for a signalfd) pass its signal mask to children: posix_spawn with a cleared mask and default handlers, or SIGTERM cannot stop them.
- **Buttons and state.**
  - **Per-person setup.** `haltia-apps` (run by `haltia-launcher` before anything else, and as `haltia-apps reload`) merges the built-in `apps.conf` (system programs without an X-B8K .desktop file: Firefox, calc, cards, term, settings), the `.desktop` programs (`X-Haltia-Home`), `~/.config/haltia/apps.conf` and the panel file (`~/.config/haltia/panel`, else `share/panel`) into `$XDG_RUNTIME_DIR/haltia/apps.conf`, numbering panel signals 1–7 then 12+ (8–11 are the system modules), and writes `waybar.json`/`style.css`/`slots`/`aliases` there; waybar runs with `-c`/`-s` on them. `haltia-launch`, `haltia-focus`, `haltia-ask` and `haltia-splash` prefer that file; never hardcode a signal number. Program buttons share the CSS class `.app`; ids with dots need CSS escaping.
  - **Calls (calls plan, step 7).** A program that rings posts a notification with urgency critical, category `call.incoming` (Gio.Notification: priority URGENT, `set_category`), the `desktop-entry` hint and a `default` action that shows its call window without answering. mako's `[category=call.incoming]` rule runs `libexec/haltia-call`: `haltia-wake` (a stream socket `/run/haltia/wake.sock` that `haltia-sleep` owns, mode 0666, heard only from root and the session user by SO_PEERCRED; it turns the screen on and restarts the idle count), `haltia-home hide`, two buzzes, `makoctl invoke -n ID default` (the newest call.incoming from `makoctl list -j`), and only when no window of that program is in front a second later `haltia-focus activate` (it picks a window not in front, so it would bury a call window already shown). The program keeps the screen on with an idle inhibitor while it rings and closes the notification after. While anything records from a non-monitor PulseAudio source (a source output neither corked nor a module's own `media.role=filter` stream without a client, read with `pactl -f json` in C: the B8000-H keeps module-echo-cancel's corked filter stream on the mic all the time) or holds `/dev/video*`, `haltia-badges` writes "mic"/"cam" to `$XDG_RUNTIME_DIR/haltia/rec` and signals 11; `custom/rec` (`haltia-meter rec`, empty text when nothing, so no module) shows `rec-mic.svg`, `rec-cam.svg` or `rec-both.svg` above the status. `pactl subscribe` runs with `LC_ALL=C`: its event lines are translated.
  - **Standards (ADR 0001).** `haltia-apps` adds `.desktop` files with `X-Haltia-Home=true` as programs under their id; `X-Haltia-Replaces=<old ids>` drops the old section and maps pinned ids to the new one. `haltia-badges` turns `com.canonical.Unity.LauncherEntry.Update` (count, count-visible; cleared when the sender leaves the bus) into the panel count (`$XDG_RUNTIME_DIR/haltia/badge/<id>` plus the button's signal, after the SigCgt check), finding the section by id or an `app_ids` word. `haltia-apps autostart` (from `haltia-launcher`) runs `/etc/xdg/autostart` entries with `X-Haltia-Autostart=true` plus `~/.config/autostart`; the GNOME helpers there stay off. `X-Haltia-Own-Feedback=true` keeps the touch filter's buzz off while it is in front. `X-Haltia-Windows` adds helper windows (b8k-vplay) to a program's app_ids; `$XDG_RUNTIME_DIR/haltia/aliases` maps old ids for `haltia-launch`. Notifications go to mako (`mako.conf`, buzz on notify through `haltia-press notify`). `haltia-badges` also follows MPRIS players (`org.mpris.MediaPlayer2.*`, matched by `DesktopEntry`): Playing/Paused goes to `$XDG_RUNTIME_DIR/haltia/play/<id>` ("<status> <bus name>"), which `haltia-launch status`/`slot` mark as ▶/‖ before the label; a tap on the front program's button while it plays runs `haltia-ask media <id>` (Пауза/Продолжить, Стоп via gdbus), and `haltia-ask pin` lists the same first.
  - **Programs** live in repositories of their own (haltia-de/*), pinned in the device repository's `linux-port/apps/sources`, and meet the shell only through the standards above. There is no shared shell module for them any more (b8k_ui is gone): their shared code is the library b8k-compat; the look is the theme, the buzz is haltia-touchguard's.
  - A section of `apps.conf`: `label`, `icon` (shown by the start-up curtain), panel `signal` (0 = no button), window `app_ids`, `exec` (and `env`). `haltia-launch` reads it with awk on every call, `haltia-focus` and `haltia-ask` once at start. The `url`/`host` web-app fields and their chromeless Firefox windows are gone.
  - The terminal has no panel button or home tile: it is in Настройки → «Для помощника», and runs a root login shell (`haltia-term` → `doas -n haltia-rootsh`, a nopass rule written with `HALTIA_DOAS=all`, the default; without it doas asks for the password, then the user's shell). `install.sh`'s `HALTIA_DOAS` (all, shell, none) chooses `/etc/doas.d/z-haltia-shell.conf`; its rules name /usr/sbin and /usr/local/sbin until 2.0. Without the poweroff rule the power menu uses `loginctl`.
  - The USB port boots as a device. The ID pin (GPIO57) reads 1 whatever is plugged in, so patch 0044 drops the connector node and the power menu's «USB: клавиатура» runs `doas -n b8k-usb host` (the device's; looked up in /usr/sbin then /usr/local/sbin, no item without it): the role switch in `/sys/class/usb_role/*/role` plus the bq24190 OTG boost through a `regulator-output` consumer.
  - `haltia-launch` tests for a running Firefox with `alive`, not `pidof`. Programs the panel started become zombies when they exit, and `pidof` lists the zombies too.
  - `haltia-focus watch` writes `$XDG_RUNTIME_DIR/haltia/launch/state` and signals waybar with `SIGRTMIN+N`. Every signal to the panel goes through one helper: `bin/haltia-panel-signal` (`N` or `reload` for SIGUSR2; the Python helpers load it as a module through their `panel()`), `tools/panel-signal.h` in C. It picks the process whose `/proc/PID/exe` is `/usr/bin/waybar`, of this user unless root, and signals only when its `SigCgt` shows the signal caught. An early signal killed waybar and caused the boot flashing.
- **Native programs instead of web apps.** Weather (`b8k-weather`, Gismeteo's open XML), news (`b8k-news`, RSS plus the story text from the page) and MAX (`b8k-max`) are Python GTK3 programs; no `apps.conf` section uses `url` now. Пасьянсы is Aisleriot (`sol`) with the `b8k-cards` GTK theme (`themes/b8k-cards`): GTK 3 CSS cannot hide widgets, so the menu bar and title are squeezed to nothing with negative margins; the toolbar and the game chooser are enlarged. The status bar's game message stays English (Alpine's Guile has no gettext), so the theme hides it. galculator's display gets 112 px on the right for «✕» (Haltia-Galculator), and `haltia-launcher` puts the shell's galculator.conf in place when there is none or only galculator's own defaults.
  - `b8k-max` runs on PyMax (the `maxapi-python` 2.4.1 wheel, pinned by sha256 in its `install.sh`, unpacked into `/usr/local/lib/b8k-max`) with telemetry off. `haltia-launcher` starts it with `--background` once a session exists in `~/.local/share/b8k-max/web.db`; closing the window only hides it, and the button reaches the same process through GApplication. It caches chats in `~/.cache/b8k-max/` and fetches photos only over https from `oneme.ru`/`max.ru`: the URLs come inside messages.
  - **Badges:** a program writes a count to `$XDG_RUNTIME_DIR/haltia/badge/<id>` and signals waybar (checking `SigCgt` first); `haltia-launch status` appends it to the label as a red number. `b8k-max` counts dialogs and groups, not channels.
- **Web-app windows** (the mechanism stays, nothing uses it).
  - Firefox's customization is the b8k-firefox repository (large toolbar, prefs, policies, `b8k-calm.js` keeping the keyboard down on a new window); `haltia-launch` runs its `b8k-firefox-profile --shell` before Firefox starts. Its chromeless web-app windows are gone (a page could pose under a trusted title); the `url`/`host` fields of apps.conf no longer open such windows. It picks up URLs that `haltia-launch` writes to `$XDG_RUNTIME_DIR/haltia/webapp.d/` and opens them in chromeless windows.
  - It builds `ALLOW` (page → title `U+2060 + label`) and `HOSTS` from the `url` and `host` of `apps.conf`. `HOSTS` limits each window to its own site; foreign pages move to a normal window.
- **Runtime files** go to `$XDG_RUNTIME_DIR`, which `pam_elogind` sets up through `haltia-session`. Never use `/tmp`.
- **Layers.**
  - waybar stays on the `top` layer. The keyboard runs on `bottom` (`--wayland-layer bottom`). Then phoc arranges the panel first, and the keyboard gets the width right of it.
  - With the keyboard on `top`, it squeezed the left panel to 440px. waybar asked for 800px again, and phoc looped (`Timeout ... configures pending` in the log), so the keyboard never appeared.
  - Moving waybar to `overlay` blanked the screen.
- **Dialogs.**
  - `haltia-ask` (the power menu and "close this program?") is a shell script around fuzzel in dmenu mode (`fuzzel-ask.ini`): C, Wayland only, on the overlay layer, so it shows in about 0.3 s (the Python GTK version took 2.3 s) and is always on top. fuzzel takes taps. Отмена, the last item, is preselected so that Enter does no harm. A choice buzzes through `haltia-press ask` (no signal).
  - `haltia-brightness` is a GTK window on the overlay layer through gtk-layer-shell (typelib `GtkLayerShell-0.1`), drawn as the same card as the fuzzel questions. b8k-paint's "start over?" uses the same fuzzel config. Programs share one header (`#dcdcda`, 88 px, title centred, "←" on the left). The palette table in `docs/shell.md` lists every colour, including the two light blues (`#c4dcf7` selected, `#99c1f1` disabled).
  - Firefox: b8k-firefox's `b8k-calm.js` takes the focus off the address bar once per window that opens on the home page, or the keyboard came up unasked.
  - The shell's GTK theme `Haltia` (`themes/Haltia`, Adwaita underneath; `haltia-launcher` exports `GTK_THEME=Haltia`; `b8k` stays as an importing alias until 3.0, which `haltia-sleep` passes on) gives programs the tall header with room for «✕» and large dialogs, so programs need not carry `HEADER_CSS` once they move to b8k-compat. Its selectors stay off what waybar draws.
  - Python GTK3 programs must call `gi.require_version("Gdk", "3.0")` as well as `Gtk`: GTK4 is installed too, and gi otherwise loads Gdk 4.
- **Ids (ADR 0004).** Programs renamed with 2.0 (`io.github.trudenboy.X` → `io.github.haltia_de.X`, Max → `io.github.haltia_de.Messenger`, command `haltia-messenger`) are matched under either id: `haltia-apps` RENAMED maps old pins (and the shell id `max`) to the new program and drops an old .desktop a new one replaces (and any NoDisplay=true one); `haltia-badges` maps LauncherEntry and MPRIS ids through the session's `aliases` and the same table. The shell's own ids are `io.github.haltia_de.Shell` (brightness) and `io.github.haltia_de.TouchSettings` (`[touch]` lists it with `haltia-touch-settings` and `b8k-touchguard-setup`).
- **Borrowed services (plan-lightening.md).** Battery from upower's DisplayDevice (`haltia-meter battery-info`, sysfs type Battery as fallback). Rotation from iio-sensor-proxy when it lets the session claim the sensor, else its own IIO reader. Notification buzz is `haltia-press notify` (feedbackd took `fbcli` events on the B8000-H with the motor enabled for a moment only, so nothing was felt; programs buzz through `/usr/libexec/haltia/haltia-press ID` too), taps from the touch filter. `haltia-hook NAME` runs /etc/haltia/hooks/NAME then ~/.config/haltia/hooks/NAME (session-start, orientation, screen-off/on). `haltia-gestures` runs lisgd on the filter's device (a swipe from the left edge brings a hidden panel back; busybox's `pkill -x` matches the full path, so actions go through `pidof`). `haltia-portals.conf` is shipped, the portals themselves are left to the image. The launcher stops stale pulseaudio, volume and rotate processes of the user at session start.
- **Device seams (ADR 0004).** The shell names no device: the backlight is `backlight=` in `/etc/haltia/device.conf` or the first in `/sys/class/backlight` (`haltia-brightness`, `haltia-sleep`); the power key `power_key=` there or the first input device with `KEY_POWER`; sleep the hook above; touch thresholds fractions of the axes; doas rules `HALTIA_DOAS`. Input events and `ff_effect` use native sizes, as x86_64 and aarch64 differ from armv7.
- **Power key** (`haltia-sleep`, root, SCHED_FIFO 10 with SCHED_RESET_ON_FORK through `pthread_setschedparam`, as musl's `sched_setscheduler` is ENOSYS; nice -10 if that fails; its children start as ordinary processes, the nightly update under `nice -n 10 ionice -c 2 -n 7`). It reads the user's `~/.config/haltia/screen` only through `read_user_file` (non-blocking open, a regular file of that uid, 4 KB).
  - A short press toggles the backlight on release. A one-second hold opens `haltia-ask power`. Ten minutes without input from any device (read ungrabbed) turn the screen off the same way (`IDLE_OFF`). 30 s after the screen goes off (never while a Mains or USB power supply is online: on the charger the system stays up with the screen off, so Wi-Fi and the messenger keep working; `external_power()`, looked at every 30 s), the device's hook `/usr/lib/haltia/hooks/suspend` (root, no arguments, returns once awake; on B8000-H its b8k-suspend) or, without it, `freeze` into `/sys/power/state` runs s2idle.
  - Programs keep the screen on or the system up with a logind "block" inhibitor (`idle` / `sleep`; haltia-kit's `Awake` takes `sleep:idle`), which `haltia-sleep` reads through `ListInhibitors` (delay ones, NetworkManager's, do not count). The old b8k-awake files are no longer read.
  - BLS latches a new PWM duty only at the start of a frame, so after each change the handler runs `grim` into `/dev/null` to make phoc draw one.
  - Programs for the session start with the uid and an allowlisted environment of the real `/usr/bin/waybar` process. That uid must belong to `/etc/haltia/session-user`.
  - `haltia-ask power` calls `doas -n /usr/libexec/haltia/haltia-poweroff off|reboot`. The doas rule is written by `install.sh`.
- **Brightness and volume.**
  - `haltia-brightness` sets the level through logind `Session.SetBrightness` and keeps it in `~/.config/haltia/brightness`.
  - `haltia-volume` steps the PulseAudio sink by 5% per press and, with a key held past 0.4 s, by 2% every 80 ms until release (its own repeat; at most 100%) and signals `SIGRTMIN+10` (the speaker in the status).
  - The hardware `Speaker` gain is pinned at step 7 by a PulseAudio profile set (`pulse/`, selected by a udev rule), because steps 0–2 crackle.
- **Tap feedback.**
  - Every panel `on-click` starts with `haltia-press <id> <signal>` (`tools/haltia-press.c`, built by `build-haltia-press.sh`). It marks `$XDG_RUNTIME_DIR/haltia/press/<id>` for 300 ms, which `haltia-launch status` and `haltia-meter` turn into the `pressed` class, and buzzes the motor for 70 ms.
  - waybar ignores `:active` on touch. Panel signals: programs and slots 1–7 then 12+, home 8, 9 unused (was brightness), the status 10, the microphone and camera mark 11. There is no drawer: the status (`custom/status`, one module) shows Wi-Fi, the speaker and a vertical battery in one row, white outlines with red only for warnings, no percentage, no plate and no highlight (waybar redraws the module just tapped only after a delay, so a press mark never shows on it); `haltia-meter status` prints the three classes and `haltia-apps` writes a background-layer rule for every combination (`status_css`). A tap runs `haltia-ask status` (the charge in the title, «Сеть: <SSID>» opening Settings at its Wi-Fi page through `HALTIA_LAUNCH_ARGS=wifi`, «Яркость и громкость» — `haltia-brightness`, now with a volume slider — and mute). Program buttons are 92 px high, the home button 84 px; play/pause and unread counts are corner marks (`haltia-launch` classes `play`, `pause`, `count-N`; `haltia-apps` writes per-program background layers with `mark-*.svg`). GTK 3 takes only one- or two-value `background-position`: `ci/check-css.py` (run by the session CI) parses the generated style, as a refused rule ends waybar and loops the session.
  - The motor is the `regulator-haptic` input device on the MT6320 VIBR LDO (patch 0039). Pulses shorter than about 50 ms are not felt.
  - The keyboard buzzes on every key press too (`wvkbd/0005-haptic.patch`, same 70 ms).
- **Start-up curtain.** `haltia-launch` runs `haltia-splash <id>` (C, `tools/haltia-splash.c`, built by `build-haltia-splash.sh` against the keyboard sysroot for cairo and pango) while a program has no window, and SIGTERMs it once the window is there. It draws the `icon` and `label` of `apps.conf` on the top layer right of the panel; SVG icons go through librsvg opened with `dlopen`, as the sysroot has no librsvg headers.
- **Hiding the panel.** The "‹" button under the clock runs `haltia-tab` (`tools/haltia-tab.c`, built by `build-haltia-tab.sh` against the keyboard's sysroot and wvkbd's `proto/`). It sends waybar `SIGUSR1` (invisible mode, exclusive zone 0) and puts a 120×44 "›" tab on the overlay layer exactly where the button was. A tap on the tab sends `SIGUSR1` again and exits. Keep the `#custom-hide` size (40 px + 2 px margins, 30 px icon) in step with `W`/`H` and the arrow in `haltia-tab.c`. `SIGUSR1` toggles, so never send it to waybar by hand while a tab is up.
- **Palette.** The frame is dark and the content light, in GNOME/libadwaita colours with the accent `#3584e4`. The palette table in `docs/shell.md` lists every file that repeats it. The keyboard colours are compiled into `wvkbd/config.b8k.h`.
